# 무목적지 카메라 안내안 독립 재검증

> 2026-11-10. 대상은 사용자가 제시한 **목적지·내비 화면 없이, 출발 후 자동으로 대기하다 약 250m 전 카메라를 한 번 알리고, 순정 내비가 안내 중이면 중복 음성을 억제하는 차량용 앱**이다. [4차 재탐색](IDEA_SCAN_ROUND4_2026-11-10.md)의 ‘우선 검증 후보’ 판단을 다시 검토했다. 제품 앱·카메라 이벤트 실주행 시연·운전자 인터뷰·공식 접수는 없다.

## 결론

**실제 불편을 줄일 가능성은 있지만, 11월 15일 1차 서류의 단독 주력 주제로 추천하지 않는다.** 앞 문서의 ‘우선 검증’은 **기술 관찰 대상으로만 유지**한다. 이 판단은 구현 불가능 판정이 아니다. 핵심 경험의 선행 서비스가 이미 있고, 현대차 순정 기능에 겹치는 부분이 크며, 남는 차이인 ‘시동 후 아무 조작 없이 자동 실행’과 ‘순정 음성 중복 억제’는 Pleos 실행·사용자 효용이 확인되지 않았다. [공식 1차 심사](https://appdevchallenge.auto-hmg.io/guide/judging-awards)는 차량특화성·창의성·SDK 활용·사업성을 모두 필수 평가한다. 배점과 합격 확률은 공개되지 않아 수치로 예측하지 않는다.

## 독립 검증 결과

| 주장 또는 위험 | 확인한 근거 | 이 안에 주는 의미 |
|---|---|---|
| 목적지 없는 카메라 알림이 새로운가 | [RadarNav 제품 설명](https://radarnav.me/)은 목적지 없는 자동 주행 알림, 주차 시 종료, 폰 잠금 중 알림 지속, CarPlay/Android Auto 차량 화면, 카메라 경고와 알림 거리 설정을 명시한다. [Waze 도움말](https://support.google.com/waze/answer/14717826?hl=en)은 앱이 열린 경우 목적지 없는 구간단속 알림을 설명한다. | ‘목적지 없이 자동으로 경고한다’는 문장을 독창성 핵심으로 쓸 수 없다. RadarNav가 실제 국내 Pleos 차량에서 동일하게 작동하는지는 별개이며 미확인이다. |
| 순정 내비에 없는가 | [현대차 ccNC 설명서](https://ownersmanual.hyundai.com/ivi/ccNC/AVNT/KOR/Korean/Settings_navigation.html)는 카메라 경고 시점과 유형, 주의 구간을 설정할 수 있다고 명시한다. 시점은 제한속도에 연동하거나 도로 종류별로 고를 수 있다. | 단순 카메라 알림·거리/유형 개인화는 순정 기능과 직접 겹친다. **이 설명서만으로 목적지 없는 상태에서도 순정 음성이 나오는지는 확정할 수 없다.** 그 차이를 실차에서 확인해야 한다. |
| 공개 Pleos API가 핵심을 뒷받침하는가 | [NaviHelper v3.0.5 이벤트 안내](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)에 `onCameraAlert`, `onCautionPointInfo`, `onNavigationStatus`가 있다. 안내는 Navigation 앱 구현에 따라 이벤트 전달이 달라질 수 있다고 명시한다. | API 선언은 **가능성**이다. 무목적지 전달·백그라운드 유지·부팅 후 자동 대기·실제 음성 억제를 보증하지 않는다. |
| SDK 자료형에 거리와 자유 주행 개념이 있는가 | 데스크탑 Gradle 캐시의 공식 AAR `NaviHelper 3.0.5`와 종속 `navi-data 3.0.4`를 `javap`으로 확인했다. `CameraAlert.getRemainDistance()`와 `NavigationStatus.FREE_DRIVE`, `ROUTE_DRIVE`가 있다. `NaviHelper` 공개 메서드에는 `getCameraAlert()` 같은 직접 조회 메서드가 없고 리스너로 받는다. | 거리 기반 판단과 무경로 상태 분기의 **자료형은 존재**한다. 실제 거리 단위·발행 빈도·250m 이전 수신·자유 주행 중 카메라 전달은 여전히 미확인이다. `FREE_DRIVE`가 있다는 사실만으로 카메라 이벤트가 그 상태에서 온다고 말하지 않는다. |
| 실제 에뮬레이터/차량에서 검증됐는가 | 데스크탑 `PleosOfficialProfile` AVD가 부팅 완료됐고 `ai.pleos.playground.sdk.navidevapp`가 설치된 것을 ADB로 확인했다. 이전 실험의 NaviHelper 경유지 미리보기는 실행됐다. 이번에는 카메라 지점을 재현할 수 있는 시나리오와 진단 리스너를 확보하지 못했다. [Virtual Console 공식 기능표](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)는 차량 신호 조작을 설명하지만 카메라 이벤트 주입을 제시하지 않는다. | **카메라 알림 작동 시험은 하지 못했다.** 이벤트 수신 여부에 대한 관측이 없으므로 성공·실패 어느 쪽으로도 해석하지 않는다. 실차·실제 도로·시동 후 자동 실행·다른 내비와의 음성 중복 시험도 없다. |
| 250m 고정이 나은가 | 250m는 시속 100km에서 약 9초, 시속 30km에서 약 30초다. 순정 기능은 제한속도 연동 시점도 제공한다. | 특정 거리 고정 자체를 사용자 이점으로 주장하기 어렵다. 출발점은 사용자 요구로 보존하되 속도별 적절성·선호를 확인해야 한다. |

## 중요한 인과 관계

1. 이 앱이 순정 내비의 카메라 정보를 `onCameraAlert`로 받아 다시 말하는 구조라면, **같은 정보를 순정 내비가 이미 사용자에게 어떻게 전달하는지** 먼저 확인해야 한다. 순정이 목적지 없이도 충분한 알림을 주면 앱이 만든 알림은 중복이다.
2. 반대로 순정이 목적지 없는 상태에서 알림을 만들지 않는다면, **그 상태에서 앱으로는 콜백을 보내는지**가 관건이다. 둘 사이의 관계는 공개 문서만으로 결론 낼 수 없다. 이 구조적 위험은 4차 조사에서 충분히 반영하지 못했다.
3. 시동 뒤 앱을 자동 실행하고 백그라운드에서 NaviHelper 연결을 유지하며 적절한 때 소리를 내는 Android Automotive/Pleos 허용 경로가 필요하다. 설치만 하면 자동으로 된다는 근거는 아직 없다.
4. ‘순정 내비가 안내 중’과 ‘순정 카메라 경고 음성이 지금 출력 중’은 다르다. `NavigationStatus.ROUTE_DRIVE`만으로 음성 중복을 완전히 검출할 수 없다. 순정 음성 시작/종료 이벤트나 확인 가능한 억제 규칙이 없다면 중복 억제는 추정 기능이다.

## 이번 1차 추천 판단

| 평가 축 | 현재 판단 |
|---|---|
| 문제의 이해 가능성 | 높음. ‘익숙한 길에서 내비를 켜지 않아도 필요한 경고’는 설명하기 쉽다. 다만 실제 운전자 빈도와 현재 대안의 실패는 직접 확인하지 못했다. |
| 차량 고유 이점 | 폰을 꺼내거나 앱을 여는 과정이 없다는 가능성은 있으나, 시동 자동 대기와 차내 음성 출력이 미검증이다. |
| 창의성 | 낮음. RadarNav의 기능 설명과 순정 카메라 설정이 상당 부분 겹친다. ‘Pleos에 탑재’만으로 새 사용자 결과를 입증하지 못한다. |
| 12월 시연 경로 | 카메라 이벤트를 원하는 시점에 재현할 수 없어 시연 시나리오가 불확실하다. 정적 UI나 가짜 경고 영상은 기능 시연으로 쓰지 않는다. |
| 지속 이용·사업성 | 운전할 때마다 쓸 수 있는 흐름이지만 기존 순정 안내가 충분하면 설치·유지 이유가 없다. 이 차이를 검증한 운전자 인터뷰가 없다. |

**따라서 독립 판단은 ‘좋은 사용 문제일 수 있으나, 현재 공모전 1차 주력 아이디어로는 약하다’이다.** 사용자가 이 아이디어를 탈락시켰다는 기록은 남기지 않는다. 우리 판단으로 주력 추천을 철회한다. 다른 미검증 후보를 대신 확정하지도 않는다.

## 다시 주력으로 올릴 수 있는 증거

1. **일반 자가용 운전자 5명**에게 최근 목적지 없는 주행, 순정·티맵·Waze·RadarNav 등 현재 해결책, 놓침 또는 중복의 실제 사례를 유도 없이 묻는다. 5명은 초기 반례 탐색 표본일 뿐 시장 통계가 아니다. ‘순정 설정으로 충분하다’는 답을 그대로 기록한다.
2. 대상 **Pleos 차량/공식 AVD**에서 목적지 없음·순정 내비 화면 아님·앱 미표시 상태에 `onCameraAlert`가 전달되는지, `remainDistance`의 단위·갱신·카메라 식별값을 기록한다. 에뮬레이터에서 카메라 재현을 못 하면 운영사에 지원 시나리오를 문의하거나 실제 시험 가능한 차종을 확보한다.
3. 재부팅·시동 후 앱 수동 실행 없이 리스너가 연결되고, 오디오 출력이 허용되며, 순정 알림과 실제로 겹치지 않는지 각각 재현한다. 상태값만으로 음성 억제 성공을 대체하지 않는다.
4. 동일한 일상 주행 과제를 순정 설정과 비교해, 운전자가 체감하는 **새 결과**가 있어야 한다. 이 네 조건이 1차 전에 없으면 제출 문안에는 구현·차별성·사용자 검증 완료라고 적지 않는다.

## 재현 메모와 범위

- 2026-11-10 데스크탑 Windows의 Pleos AVD에서 `adb devices`는 `emulator-5554 device`, `getprop sys.boot_completed`는 `1`, 설치 패키지 목록에는 `ai.pleos.playground.sdk.navidevapp`가 있었다. 검사 후 AVD를 종료했다.
- Gradle 캐시의 `NaviHelper-3.0.5.aar`와 POM이 `navi-data 3.0.4`를 참조함을 확인했다. 두 AAR의 `classes.jar`에 `javap`을 적용해 위 자료형·메서드 이름을 확인했다. 로컬 SDK 구조 확인이며 서비스 이벤트 수신 실험은 아니다.
- 공식 자료는 2026-11-10 웹에서 재확인했다. RadarNav의 설명은 제공사 주장으로, 국내 특정 차종의 실제 성능이나 보급률을 증명하지 않는다. 현대차 설명서도 차종·사양에 따라 메뉴가 다를 수 있다고 명시한다.
