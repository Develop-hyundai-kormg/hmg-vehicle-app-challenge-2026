# 1차 제출 후보 검토: 할인 경계

판단일: **2026-11-12 KST** · 상태: **기획서 초안이 있는 후보, 1차 제출 추천은 보류**. 앞서 ‘1차 제출 주제’로 선정했으나, 사용자가 검증 여부를 지적한 뒤 핵심 가치 증거가 없다는 점을 재판단했다. 같은 날 추가 시험에서 **공식 샘플의 NaviHelper 현재 경로거리 콜백**은 Pleos AVD에서 확인했다. 운전자 반응, 실차 동작, 자체 제품 앱 APK는 확인하지 않았다. [검증 감사](INSURANCE_MILEAGE_VALIDATION_AUDIT_2026-11-12.md) · [경로거리 실행 시험](NAVI_DESTINATION_DISTANCE_RUNTIME_PROBE_2026-11-12.md)

## 한 줄 소개

**〈할인 경계〉는 자동차보험 주행거리 할인특약 가입자가 출발 전에 실제 차량 누적거리와 지금 설정한 내비 경로를 대조해, 이번 이동이 다음 보험료 환급 구간에 어떤 영향을 줄지 보는 Pleos 차량용 앱이다.**

핵심은 주행거리 기록이나 일반 길찾기가 아니라 **구간 경계 앞의 한 번의 이동 결정**이다. [DB손해보험의 공개 할인표](https://m.directdb.co.kr/comm/bnf/evt/atarcDstTtyView.do?pageDvn=trvDstc)에는 개인승용 30세 이상 일반승용 예시로 연간환산거리 **10,000km 이하 13.2%, 10,000~10,500km 8.3%**가 표시된다(2026-11-12 확인). 할인 계산의 기준 보험료를 **가정상 100만 원**으로 두면 구간 차이는 4.9%포인트, **4만 9천 원**이다. 이는 실제 계약자의 환급액이 아니다.

가상의 1년 계약(2026-11-15~2027-11-15)이 끝나기 3일 전인 **2027-11-12**, 특약 기준 주행거리가 9,850km이고 남은 계획 운행이 없다고 가정한다. 현재 내비 경로 160km를 그대로 운행하면 10,010km가 되어 위 예시 구간이 달라진다. 앱은 **‘이번 경로를 가면 경계를 10km 넘을 수 있음’**과 두 경우의 예상 할인 차이를 보여준다. 운전자는 그 정보를 보고 경로·동행차량·대중교통 여부를 직접 결정한다. 운행을 막거나 보험료를 확정하지 않는다.

## 문제가 실제인 이유와 기존 방식

- [금융감독원·보험업계의 마일리지 특약 제도 설명](https://kiri.or.kr/PDF/weeklytrend/20220404/trend20220404_2.pdf)과 [DB손해보험 공식 안내](https://m.directdb.co.kr/comm/bnf/evt/atarcDstTtyView.do?pageDvn=trvDstc)는 주행거리별 보험료 할인과 만기 정산 구조를 확인시킨다. 사용자가 가입한 보험의 구간·적용 방식은 보험증권이 기준이다. DB는 15,000km를 넘더라도 특약 가입 자체에 따른 추가 불이익은 없다고 안내한다. 별도로 [금융감독원 소비자경보](https://m.samsungfire.com/download/consumer/ca_d12.pdf)에는 **선할인** 계약자의 약정 거리 초과로 추가보험료가 발생한 민원 사례가 있다. 계약 방식에 따라 초과의 의미가 다르다.
- 보험사 앱은 가입·주행거리 증빙·환급을 처리하고, [현대차 블루링크 데이터 제공 고지](https://developers.hyundai.com/api/v1/download/privacy_policy/20211230)에는 보험사에 누적거리를 제공하는 사례가 있다. 해외 [Sonnet Shift](https://www.sonnet.ca/shift-faqs)는 예상 연간 주행거리와 예상 할인율을 앱에서 이미 보여준다. 국내 [차셈 계산기](https://chasem.co.kr/insurance/mileage/)도 구간까지 남은 거리를 계산한다. **자동 거리 조회·할인 예측·구간 계산을 새 기능으로 주장하지 않는다.**
- 공개 조사에서 확인한 차별화 가설은 **운전자가 지금 선택한 순정 내비 경로를 보험 구간의 임계값·금액에 즉시 대조하는 차 안의 결정 화면**이다. 보험사 앱과 내비를 따로 열어 km를 계산하는 과제를 줄일 수 있는지는 실제 사용자 비교가 필요하다. 동일 경험의 선행 앱이 없다고 단정하지 않는다.
- 월말이나 보험 만기 근처에 확인할 이유가 큰 기능이다. 매일 쓰는 범용 앱으로 포장하지 않는다. 타깃은 거리 할인특약에 가입했고 다음 할인 구간에 가까운 Pleos 차량 운전자다.

## 제품 흐름과 계산 경계

1. **주차 중 최초 설정:** 보험증권의 주행거리 측정 시작일·계기판 km, 만기/최종 측정일, 현재 관심 구간의 거리 상한과 인접 두 구간의 환급액 또는 할인 계산 기준 금액·율을 입력한다. 가입 보험사가 정한 연간환산 규칙도 확인한다. 첫 버전은 [DB의 공개 표](https://m.directdb.co.kr/comm/bnf/evt/atarcDstTtyView.do?pageDvn=trvDstc)를 예시 프리셋으로 제공하고, 실제 계약값을 수정 가능하게 한다. 보험사 계정 연동이나 보험료 청구는 하지 않는다.
2. **출발 전·주차 중:** Pleos Vehicle SDK `getOdometer().getCurrentDistanceDriven()`로 현재 계기판 누적거리를 읽는다. capability·단위·유효성을 확인해 계약 기준 누적거리 증가분을 계산한다. `getDestinationInfo()`의 `remainDistance`가 실제로 전달되면 **편도** 경로거리와 합산한 두 시나리오를 보인다. 귀로 거리를 근거 없이 두 배로 만들지 않는다.
3. **결과 화면:** `이번 길을 가지 않으면`과 `현재 경로를 운행하면`을 비교한다. 보험 만기까지 추가 운행이 없다는 단순 가정을 기본으로 명시하고, 운행 기록이 쌓였을 때만 최근 추세 예측을 별도로 제공한다. 경계 통과 가능성·가정의 민감도·보험사별 최종 산정 차이를 함께 표시한다. 금액은 **예상 할인 차이**이고 보험사 확정 환급액이 아니다.
4. **선택과 사후 확인:** 운전자가 원하면 활성 경로에서 NaviHelper `changeRouteOption(SHORT_DISTANCE)`를 요청하고, 변경 전후 거리·시간 콜백이 모두 나왔을 때만 차이를 보여준다. 이후 주차 중 다시 누적거리를 읽어 실제 증가분을 기록한다. 주행 중 복잡한 계산 화면이나 경로 변경 조작을 요구하지 않는다.

NaviHelper 거리 콜백은 **AVD의 공식 샘플에서 실행 확인**했다. 좌표 요청 경로 12km/20분에 `remainDistance=12000`, `remainTime=1200`이 반환됐다. 원본 POI 샘플은 요청 좌표와 콜백 목적지가 일치하지 않았으므로, 앱은 목적지 일치·경로 활성·단위 확인 뒤에만 계산해야 한다. 제품 앱에서 Vehicle SDK 누적거리와 이 콜백을 결합한 실행은 아직 없다. Odometer 값이 읽히지 않거나 단위·측정기간을 확인할 수 없으면 금액을 숨긴다. 계약의 특정 면책·선할인 정산 규칙까지 임의로 추정하지 않는다.

## 검증을 통과할 경우 공식 양식 1~6번에 옮길 초안

1. **한 줄:** “자동차보험 마일리지 할인 경계를, 지금 차가 읽은 누적거리와 출발 경로로 미리 확인합니다.”
2. **기획 배경:** 마일리지 특약은 km 구간별 할인 폭이 다르다. 운전자는 보험증권의 기준 거리, 차량 계기판, 내비 경로 거리를 따로 확인해야 이번 이동이 할인 구간에 미치는 영향을 알 수 있다. 특히 만기 직전 경계에 가까울 때 작은 거리 차이가 환급액을 바꾼다.
3. **기능·차량 특화:** Pleos Vehicle SDK의 실제 누적거리 조회와 NaviHelper의 현재 경로거리를 결합해 ‘이번 길 전/후’ 예상 할인 구간을 비교한다. 보험사의 공식 정산을 대체하지 않고 사용자 계약값을 사용한다.
4. **사용 장면:** 가상 계약의 보험 만기 3일 전 운전자가 주차 상태에서 목적지를 설정한다. 앱이 특약 기준 9,850km와 경로 160km를 대조하고, 추가 운행이 없으면 할인 구간이 달라질 수 있음을 보여준다. 운전자가 다른 경로 또는 이동수단을 선택하고, 나중에 실제 주행거리 증가분을 확인한다. 수치는 가상 시나리오다.
5. **개발 계획:** 1차는 계약 입력·단위 검증·두 시나리오 계산·주차 화면을 구현한다. Pleos AVD에서 Vehicle SDK 누적거리 **정적 조회**와 공식 NaviHelper 샘플의 **현재 경로거리 콜백 12,000m**를 각각 실행 확인했다. 한 제품 앱에서의 결합, 경로 옵션 변경, 실제 차량 권한은 다음 검증 항목이다. 12월에는 자체 APK에서 계약 입력 → SDK 거리 조회 → 경계 계산 → 내비 경로 반영을 실동작 시연한다.
6. **기대효과·확장:** 초기 사용자는 보험 마일리지 특약의 다음 구간이 가까운 Pleos 운전자다. 보험 갱신기와 장거리 운행 전 재확인이 주요 사용 장면이다. MAU는 `Pleos 활성차량 × 특약 가입 비율 × 구간 근접 비율 × 앱 설치율 × 월 재방문율`로 추정하되, 아직 값은 조사하지 않았다. 여러 보험사 지원·제휴는 약관 유지와 사용자 가치가 확인된 다음에 검토한다.

## 11월 14일까지의 반증 관문과 12월 시연

- **SDK:** Pleos AVD의 좌표 요청에서 `onDestinationInfo(remainDistance=12000, remainTime=1200)` 수신과 내비 화면 12km/20분 일치를 [실행 확인](NAVI_DESTINATION_DISTANCE_RUNTIME_PROBE_2026-11-12.md)했다. 다음은 자체 앱의 Vehicle SDK 누적거리 결합, 원본 POI 요청 불일치 원인, 활성 경로 옵션 전후 수치다. [공식 목적지 API](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations), [경로 옵션 제약](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/NaviHelper/routes).
- **사용자:** 실제 자동차보험 마일리지 특약 운전자 3~5명의 최근 확인 행동을 묻고, **경계에 가까운 시나리오**를 보험사 앱+내비와 앱 시안으로 각각 수행시켜 계산 시간·오류·선호를 비교한다. 경계 근처에 실제로 가지 않는다면 인터뷰만으로 수요를 과장하지 않는다.
- **계산:** 다른 보험사·가입일·차종·선할인/후할인 계약 샘플로 표시 조건을 검증한다. 본문 사례의 날짜·산식·4만 9천 원 차이는 가상 계약 계산으로 재현한다. 계약 정보를 모르면 금액 대신 필요한 정보를 안내한다.
- **2차 최소 시연:** 정차 상태에서 자체 Pleos 앱으로 계약 예시 입력 → Vehicle SDK 실제 반환값 0.0을 조회하고 ‘에뮬레이터 차량값’으로 표시 → 별도 예시 계기판값을 넣어 할인 계산 → **활성 경로거리 콜백을 목적지 일치 검사 뒤 붙인다.** 고정 AVD 값을 실제 주행거리 변화처럼 연출하지 않는다. 과제 비교에서 기존 방식보다 낫지 않으면 이 주제의 차별성을 다시 판단한다.

## 증거 수준

- **실행 확인:** Windows Pleos AVD의 Vehicle SDK 누적거리 READ capability·현재값 0.0, Linux Pleos AVD의 공식 NaviHelper 샘플 `onDestinationInfo` 거리 12,000m/시간 1,200초와 내비 화면 일치. [기술 검증 기록](TECHNICAL_VALIDATION.md), [경로거리 재현](NAVI_DESTINATION_DISTANCE_RUNTIME_PROBE_2026-11-12.md)
- **공식 문서 확인:** DB손해보험의 할인 구간과 산식, 금융감독원/보험업계 특약 구조, Pleos SDK API와 주행 중 앱 제한. [DB 공식 표](https://m.directdb.co.kr/comm/bnf/evt/atarcDstTtyView.do?pageDvn=trvDstc), [Pleos 정책](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy), [공모전 평가](https://appdevchallenge.auto-hmg.io/guide/judging-awards)
- **가설·미확인:** 한국 운전자의 실제 과제 이득, 보험 만기 임박자의 재방문, 자체 제품 앱의 Vehicle SDK+NaviHelper 결합과 경로 옵션 변경, 실차 배포 권한, 제휴·수익성. 공식 심사 배점과 합격 가능성은 알 수 없다.
