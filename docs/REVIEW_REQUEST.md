# 팀원 AI 독립 검토 요청

이 요청의 최초 버전으로 팀원 보고서 3건을 받았고, [2026-11-09 독립 재검증](INDEPENDENT_REVIEW_2026-11-09.md)에 서로 다른 추천과 Pleos 실험을 대조했다. 추가 검토자는 그 문서의 **실행 확인·실패·미확인**을 먼저 확인하고, 다른 팀원의 결론에 동의하기 전에 독자적인 반례를 찾아야 한다. 보고서는 Markdown으로 받아 이 저장소의 Issue 또는 각자 문서로 공유한다.

```text
이 저장소 README.md, docs/CONTEST.md, docs/PRODUCT_VISION.md,
docs/TECHNICAL_VALIDATION.md, docs/INDEPENDENT_REVIEW_2026-11-09.md,
docs/SUBMISSION_PLAN.md를 먼저 읽어라.
읽을 수 없는 파일은 읽었다고 가정하지 말고 알려라.

너는 현대자동차그룹 2026 차량용 앱 개발 공모전을 준비하는 팀의
독립 검토자다. 주제 확정·팀 자체 제품 앱·실사용자 인터뷰는 없다.
데스크탑에서 공식 Pleos 샘플과 별도 AAOS 진단 앱은 실행했다.
기존 문서는 검증 대상인 가설이다. 이번에는 조사와 제안만 하며,
코드 작성·외부 문의·공모전 접수는 하지 마라.

공식 공모전 안내와 Pleos 문서, 기존 제품의 1차 자료를 직접 확인하라.
핵심 주장은 '실행 확인 / 공식 문서 확인 / 추론 / 미확인'으로 분류하고,
링크와 확인 날짜를 붙여라. API 이름을 실제 접근·동작의 증거로
해석하지 마라. 검색에서 못 찾았다는 이유로 독창성을 확정하지 마라.

다음 순서로 Markdown 보고서를 작성하라.
1. 이 저장소의 중요한 사실 오류·누락·오래된 정보와 수정 근거.
2. 기존 후보 A~E를 사용자 문제, 기존 대안, 차량 고유 가치,
   Pleos 데이터·권한, 1차 최소 시연, 2차 앱 구현 가능성,
   가장 빠른 탈락 시험으로 비교.
3. 사용자의 원래 요구인 '시동 후 자동 대기, 내비 목적지·화면 없이
   약 250m 전 카메라 알림, 순정 내비 작동 시 자체 경고 억제'를
   기술·기존 서비스·주행 정책 관점에서 별도 검토.
4. 현재 후보보다 나은 새 후보가 있으면 최대 2개만 제안.
   각 후보에 실제 반복 문제, 기존 해결책, Pleos 우위,
   필요한 API/데이터, 1차 시연, 2차 구현, 재사용 이유,
   탈락 조건을 제시. 적합한 후보가 없으면 '없음'이라고 써라.
5. 공식 양식 1~6번에 무엇을 쓰고, 영상/목업/앱/소스+APK 중
   어떤 조합을 1차에 낼 수 있는지 현실적 계획을 제시.
   MAU·유지율은 실적처럼 꾸미지 말고 산식과 가정을 제시.
6. '후보 1개 추천 / 추가 검증 후 결정 / 현재 추천 후보 없음' 중
   하나를 선택. 반대 근거와 1차 마감 전 최우선 확인 3개도 포함.
7. AI가 확인할 수 없어 팀원 본인이 답해야 하는 사실을 나열.

공식 배점과 합격 확률은 공개되지 않았으므로 숫자를 만들지 마라.
서로 다른 팀원 AI의 답변을 합치지 말고 독립 보고서로 제출하라.
```
