# 공식 접수양식 작품 소개 1~6번 초안 — 다음 운전자

> **사용 금지 · 2026-11-10:** 사용자가 이 주제를 탈락시켰다. 이 문안은 당시 이력이며 현재 접수양식에 옮기지 않는다. [새 후보 조사](COMMUNITY_IDEA_SCAN_2026-11-10.md).

> **팀 피드백 전 문안 · 2026-11-09.** 아래 `가설/계획`을 실제 결과처럼 바꾸지 않는다. 팀원 이름·연락처·서명은 저장소에 두지 않고 공식 DOCX에만 작성한다. [작업 주제와 탈락 조건](FIRST_ROUND_DIRECTION_2026-11-09.md)

## 1. 앱 한 줄 소개

**다음 운전자**는 가족이 한 자가용을 번갈아 쓸 때, 이전 운전자가 다음 출발 전 처리할 일을 차 안에 남기고 다음 운전자가 차량의 현재 주행 가능 거리와 함께 확인하는 정차 중 인계 앱입니다.

## 2. 기획 배경

**문제 가설:** 가족의 공동 차량에서 충전·주유 확인, 물건 회수, 정비 예약처럼 다음 운전자에게 넘겨야 할 일이 운전 교대 사이에 놓칠 수 있다. 현재는 대화·전화·메신저 또는 차량 상태 앱을 사용할 수 있다. [마이현대 차량 공유](https://www.hyundai.com/kr/ko/digital-customer-support/app/myhyundai/car-share)는 가족 간 차량 기본 정보와 일부 차량 관련 기능을 공유하므로 강한 대안이다. 다만 '다음 운전자가 출발 전에 끝내야 할 조치'의 기록·확인 흐름이 필요한지는 아직 검증하지 못했다.

**제출 전 채울 사실:** 최근 30일 교대 사례 `[n건]`, 그때 실제 누락/재확인한 행동 `[사례]`, 현재 대안 `[앱·통화·차량 화면]`, 대안보다 줄어든 단계 또는 누락 `[과제 비교 결과]`. 확인하지 못하면 수요·효과의 수치 주장을 삭제한다.

## 3. 주요 기능과 차량 특화 요소

1. 이전 운전자가 **정차 중** 다음 사람이 알아야 할 조치 한 건을 선택·수정·삭제한다. 자유 메모는 짧게 제한한다.
2. 다음 운전자가 같은 차량의 앱을 열면 대기 중 조치와 차량 SDK의 **남은 주행 가능 거리**를 조회 시각과 함께 본다. 지원되는 차종에서는 EV SOC 또는 누적거리를 보조 정보로 고려한다. 단위는 m를 km로 변환한다. 데이터를 못 읽으면 숫자를 꾸미지 않고 `확인 불가`로 표시한다.
3. 완료/보류를 누르면 **같은 차량의 다른 사용자 계정에도 상태가 전달되어야 한다.** AAOS는 사용자별 앱 데이터를 분리하므로 단순 로컬 저장으로는 제품 핵심을 구현할 수 없다. 안전한 계정 연결·공유 저장·네트워크 및 오프라인 처리는 **현재 미설계·미검증**이다. [AAOS 사용자 데이터 설명](https://source.android.com/docs/automotive/users_accounts/accounts). 시동 자동 팝업이나 운전자 자동 식별은 주장하지 않는다.
4. 차량 화면에 놓인 조치와 현재 차량값의 결합이 핵심 가설이다. SDK 값을 붙인 메모가 실제로 메신저보다 나은지는 팀 시험으로 확인한다.

## 4. 주요 사용 시나리오

가족 운전자 A가 운행을 마치고 합법적으로 정차한 뒤 앱을 열어 `다음 장거리 운행 전 충전 확인`을 남긴다. 다른 AAOS 계정의 다음 운전자 B는 출발 전 **직접 앱을 열어** 공유된 조치와 차량에서 새로 읽은 주행 가능 거리, 조회 시각을 본다. B는 차량 계기판/공식 경로 계획과 대조해 필요한 행동을 정하고 `완료` 또는 `보류`를 누른다. 상태값이 없거나 오래됐으면 앱은 판단을 대신하지 않고 확인 불가로 표시한다. 주행 중 입력은 제한한다. **이 계정 간 전달은 미구현이다.**

**미검증:** A→B 계정 간 전달·실제 사용, 교대 시 앱 재방문, SDK 값 변화, 대상 차종 적용, 주행 제한 구현. 위는 계획 시나리오다.

| 11월 10~11일 | 일반 자가용 공동 운전자 최근 사례, 메신저·마이현대 과제 비교. 팀원 독립 반론과 네 항목 심사 관점 대조 | 사례나 차별점이 없으면 주제 교체를 결정 |
| 11월 11~13일 | Pleos 앱에서 서로 다른 AAOS 계정 간 인계 공유 경로를 먼저 검증하고, 조치 저장/완료, Vehicle SDK 잔여 거리 읽기·단위 변환·실패 처리, 정차/주행 화면 제한 구현 | 계정 간 공유가 불가하면 주제 재선정; 같은 계정 재실행만으로 2인 인계를 주장하지 않음 |
| 11월 13~15일 | 공식 양식 1~6번 사실 대조, 실제 앱 화면 녹화 가능 여부 확인. 소스와 release APK는 새 설치 시험 성공 시에만 선택 제출 | 가산점 자료 없이 DOCX만 접수할 수 있으나 2차 실행 앱은 여전히 필요 |
| 11월 16일~12월 2일 | 2차용 새 설치·재실행·오류 처리·시연 연습 | 실제 앱 시연이 안 되면 2차 필수 조건을 충족하지 못함 |

현재 팀 자체 제품 앱과 APK는 없다. Vehicle SDK의 정적 조회만 공식 샘플/별도 실험에서 확인했다. `getRangeRemainingDistance()`는 deprecated로 표시돼 있어 대체 API·차종별 지원도 확인해야 한다. **계정 간 공유 경로는 제품의 필수 미해결 조건**이다. 정확한 앱 권한·API 동작은 자체 빌드에서 다시 검증한다. [실험](../experiments/consumer-signal-probe/README.md), [Pleos 개발 시작](https://document.pleos.ai/en/docs/pleos-only/getting-started), [주행 안전 설계](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline)

## 6. 기대효과와 발전 가능성

검증할 효과는 **인계 조치의 누락과 확인 왕복 감소**다. 기존 메신저/차량 앱과 동일한 과제를 수행한 뒤 다음 운전자가 필요한 조치를 정확히 기억·실행했는지, 단계 수와 확인 시간을 비교한다. 아직 측정 결과는 없다.

초기 타깃은 Pleos 지원 차량을 공동 사용하는 2인 이상 가구다. 예상 MAU는 `Pleos 지원 차량 수 × 공동 운전 비율 × 설치 비율 × 월 1회 이상 인계 비율`로 추정하되 네 입력값을 확인하기 전에는 숫자로 제시하지 않는다. 재사용률은 첫 인계 완료 가구 중 다음 달에도 1건 이상 인계한 가구 비율로 정의한다. 시장 크기·수익 모델은 현재 미확인이다. 기능이 검증되면 공유 차량의 다른 정차 중 업무로 확장 가능하지만, 마이현대·기존 앱과의 중복 및 차량 간 동기화 문제를 먼저 해결해야 한다.

## 공식 양식에 옮기기 전 필수 입력

- 4명 팀원 정보·학적·부문 확인, 개인정보 동의와 전원 서명·날짜, 대표자와 전원 CC
- 실제 운전자 사례와 대안 비교 결과 또는 해당 주장 삭제
- 자체 앱·영상·APK의 **실제** 준비 상태와 지원 API·권한 결과
- 공모전 공지·양식 최신판 및 비공개 저장소 심사용 접근 확인
